# Runtime logging and data lifetime

Logging is structured JSON for lifecycle, API/runtime versions, bound loopback/port, allowlisted model ID, health/error code and bounded operational timings/counts. No arbitrary request/header/filename field enters logs. Fatal/unhandled failures emit only `INTERNAL_ERROR` and shut down; no raw exception or stack is rendered. Normal native stderr is capped and drained, never retained/logged. HTTP errors use fixed safe messages without paths, usernames, command lines, checksums or diagnostics. Health/version exposes only existing compatible status/version/model/platform/arch metadata.

Forbidden by default: audio bytes, transcript, expected answer, question text, upload filename, temp/absolute paths, user identity, native stderr or raw exception strings. Structured serialization bounds the allowed dynamic values and prevents line injection. Random internal request IDs encode no learner/task information; there is no transcript cache, crash-report upload or telemetry. Future diagnostic export must be explicit opt-in with the same content exclusions. Test-only GC/stress counters are not product telemetry.

Audio goes from MediaRecorder/Blob → bounded streamed multipart → private request input → private normalized WAV → native processes. Successful response is sent only after request files are deleted. Abort and ordinary errors take the same finally cleanup route and release the one slot. Cleanup/storage failure prevents further transcription and reports non-ready health. An unclean kill can leave private files; the next safe restart removes only generated stale entries after owner checks. A real cleanup failure can leave private files until recovery; no promise of infallible deletion is made.

Transcript goes from bounded validated native stdout → runtime memory/HTTP → frontend state; IndexedDB only changes on explicit learner save. The runtime never writes Attempts/ErrorRecords/ReviewItems/mastery and never receives a dedicated expected-answer field. OS core/crash dumps, swap, backups and filesystem failure are outside ordinary runtime deletion guarantees; packaging must review dump/swap policy. Logs, stress artifacts and committed audit summaries exclude private learner content.

Environment audit: production has no PTE/test environment override for Host, Origin, native/model paths, shell or resource limits. Native children retain only fixed locale and Windows SystemRoot. Node interpreter startup variables cannot be neutralized after code has already loaded; 05.09 must sanitize the launcher. `os.tmpdir()` uses standard OS temp selection (including TMPDIR/TEMP/TMP where applicable), with unchanged private ownership/lock/symlink checks. This documented OS input cannot disable those checks; packaging should select a controlled per-user tempBase internally and sanitize inherited temp variables. Test artifact/GC/process-mode injection lives only in test/stress launchers, not production runtime:start.
